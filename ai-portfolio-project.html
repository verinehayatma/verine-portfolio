Why This Counts as a Project

Directing AI is a different skill than using it

Anyone can ask an AI tool to "make a portfolio." Getting a multi-page, cohesive, accurate site out of it — one that represents real projects correctly and looks intentional rather than generic — takes the same skills as running any other project: clear direction, iteration, and knowing what "good" looks like.

What I actually did

I didn't just describe a portfolio once and accept the first result. Every page went through rounds of feedback — adjusting the color palette to fit my taste, deciding which projects deserved their own detailed case study versus a simple summary, and catching where the AI's first draft didn't match the real story of a project.

I also supplied and curated all of the actual substance: uploading real reports, real screenshots, real social content, and real photos, and directing where each one belonged and how it should be framed — rather than letting the AI invent placeholder content.

Business analyst, marketing, and data analyst roles increasingly involve directing AI tools to move faster — not just writing prompts, but reviewing output critically, catching errors, and knowing when something needs another round. This project is a working example of exactly that.

The Process

What the back-and-forth actually looked like

Building a real site with an AI tool means a lot of small decisions, not one big prompt. Here's what that looked like in practice.

Direction

Setting the design language

Specified a color palette, tone (clean but fun), and readability requirements (minimum font size, clear hierarchy) up front, then adjusted as pages were built — like adding a warmer accent color to keep an all-blue site from feeling flat.

Structure

Deciding the information architecture

Chose to split the site into a homepage plus individual case study pages once it became clear a single long page couldn't hold six different projects without losing clarity.

Content QA

Catching what AI got wrong or generic

Replaced illustrative mockups with real screenshots once I had them, corrected assumptions the AI made about team credit and project framing, and added specific numbers and context only I knew.

Technical follow-through

Getting it actually live

Walked through repo setup, file uploads, and GitHub Pages configuration — including troubleshooting a 404 when a file got deleted and fixing broken image links, which is where "it works in the demo" turns into "it works for real."

Skills Demonstrated

What this project actually shows

AI collaboration

Directing an AI tool through iterative rounds of feedback rather than accepting first drafts — the core skill behind effective prompt engineering.

Content curation

Deciding what real material (reports, screenshots, social posts, photos) belonged where, and rewriting AI-generated framing to match the actual story.

Quality control

Catching inaccuracies, generic phrasing, and placeholder content before publishing — treating AI output as a draft, not a final answer.

Basic technical literacy

Comfortable enough with Git, GitHub, and file structure to deploy and debug a real website, not just describe one.

Design judgment

Knowing what "on brand" and "readable" mean well enough to give useful feedback on color, typography, and layout.

Project management

Coordinating six interconnected pages, multiple content types, and a phased rollout — the same instincts that apply to any multi-part deliverable.
