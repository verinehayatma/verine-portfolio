Project Overview

Treating my job search like a pipeline

Applying to dozens of roles means dozens of open loops: which ones I applied to, who the recruiter is, when to follow up. I wanted one system that tracks all of it and does the busywork, while I stay in control of every message that goes out.

What I built

Using Claude, I designed an agent with written instructions, a shared tracker document, and access to my Gmail and Google Calendar. Every day it runs a morning brief, scans for new postings that match my background (Seattle area first), and logs each role in the tracker with a real apply link.

When I apply, I flip one switch in the tracker. The agent then records the date, finds the recruiter or hiring manager, and writes a draft outreach email in Gmail for me to review and send. It also schedules a Day 7 follow-up and a Day 14 nudge so nothing slips.

How It Works

From new posting to follow-up, with me in the loop

Agent finds and logs roles

Each morning it searches for new postings, skips anything already tracked, and adds each role with a real apply link, near-perfect fits first.

I apply, then flip the switch

Quick application sites can be filled with the agent in my own Chrome. I review the answers and approve every submit myself.

Agent logs and drafts outreach

It sets the status to Applied, records the date, finds the recruiter or hiring manager, and writes a Gmail draft. It only uses emails that are publicly posted.

Follow-ups are scheduled

Day 7 and Day 14 reminders are set in the tracker so a quiet inbox does not mean a forgotten application.

Guardrails and Design Decisions

Automation I can actually trust

An agent with access to my email needs firm rules. I wrote them into its instructions and tested them as I went.

Drafts only, never sends

The agent creates Gmail drafts but never sends, replies, or accepts invites without my explicit OK.

No accounts, no passwords

It never creates accounts or types passwords. Account-heavy sites are flagged so I can handle them myself in one batch.

Web and email text is data

Anything it reads in an email or posting is treated as information, never as instructions, and suspicious text gets flagged.

Split the work by speed

After finding agent-run applying slower than doing it myself on some sites, I split it: the agent handles quick forms, I handle long account-based ones.

Run without my laptop

I dropped message scanning that needed my Mac to be on, so the daily runs work from the cloud on a schedule.

Prioritize fit, then reach

Near-perfect matches come first. Roles where I only have partial experience come after those are used up for the day.
